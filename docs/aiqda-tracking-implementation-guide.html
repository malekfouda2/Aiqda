Tracking Implementation Guide

This guide documents Aiqda’s current analytics architecture and the exact steps required to complete Google Tag Manager, Google Analytics 4, and Meta Pixel configuration using the live implementation now present in the codebase.

1. Current Implementation Status

Current model: Aiqda now uses a GTM-managed GA4 architecture. Direct GA4 event dispatch from frontend code has been removed.

The frontend currently does the following:

  • Pushes structured events into window.dataLayer for GTM.
  • Sends internal product analytics events to the backend for Aiqda’s own reporting.
  • Sends Meta Pixel events through fbq.

The frontend no longer loads gtag.js or sends GA4 events directly. GA4 should now be configured entirely inside Google Tag Manager.

2. Aiqda Event Model

The following key events are already produced by the site and pushed into the GTM data layer:

page_view session_start page_engagement scroll_depth search file_download navigation_click outbound_click cta_click sign_up generate_lead begin_checkout add_payment_info purchase aiqda_user_context aiqda_user_context_cleared
The same event stream is also used for internal dashboard analytics. GTM should therefore only be used for external analytics/tagging destinations and should not replace the internal backend event ingestion.

4. GTM Configuration Steps

4.1 Create The Google Tag

  1. Open Google Tag Manager.
  2. Select container GTM-MF72G76S.
  3. Go to Tags and create a new tag.
  4. Select tag type Google tag.
  5. Enter your GA4 Measurement ID: G-DXPP8Z7FVT.
  6. Set the trigger to Initialization - All Pages.
  7. Save the tag.

5. GA4 Property Configuration

5.1 Custom Definitions

Create event-scoped custom dimensions in GA4 for the most important custom parameters:

  • locale
  • visitor_id
  • session_id
  • destinationPath
  • maxScrollPercent

If you later send user properties through GTM, create user-scoped custom dimensions for:

  • user_role
  • subscription_status

5.2 Key Events

Mark these as GA4 key events:

  • sign_up
  • generate_lead
  • begin_checkout
  • purchase
  • Optionally add_payment_info if you want to analyze payment-step drop-off.

6. Meta Pixel Configuration

Meta Pixel ID 1022093374056344 is already integrated in the frontend code.

The implementation currently maps the following events:

  • PageView
  • Search
  • CompleteRegistration
  • Lead
  • InitiateCheckout
  • AddPaymentInfo
  • Purchase
  • Custom Meta events for everything else

7. Testing Procedure

7.1 GTM Preview

  1. Open GTM and click Preview.
  2. Connect to the target site URL.
  3. Navigate through the site and confirm the expected events appear in Tag Assistant.

7.2 GA4 Realtime

  1. Open GA4 Realtime.
  2. Perform the same actions on the site.
  3. Confirm events are arriving in Realtime.

7.3 Meta Events Manager

  1. Open Meta Events Manager and select Pixel 1022093374056344.
  2. Use Test Events.
  3. Confirm PageView, Lead, InitiateCheckout, and Purchase appear when expected.
Use GTM Preview before publishing container changes. This reduces the risk of duplicate or malformed GA4 events.

8. Production Notes

For production builds, ensure the frontend environment includes:

  • VITE_GTM_CONTAINER_ID=GTM-MF72G76S
  • VITE_META_PIXEL_ID=1022093374056344

The old VITE_GA4_MEASUREMENT_ID value can remain documented for reference, but GA4 dispatch now happens through GTM rather than direct frontend code.
